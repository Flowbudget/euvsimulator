4. NEW SOURCE OF TRUTH

HC_EV_NM = 1239.8419840550368 eV·nm (exact from CODATA 2018 Planck constant and speed of light)

EUV_WAVELENGTH_NM = 13.5 nm (configurable via SimulationConfig)

EUV_ENERGY_EV = HC_EV_NM / EUV_WAVELENGTH_NM = 91.84014696703977 eV (derived, not hardcoded)

All conversions use HC_EV_NM:
- nm_to_eV(wavelength_nm) = HC_EV_NM / wavelength_nm
- eV_to_nm(energy_eV) = HC_EV_NM / energy_eV

5. UNIT CONVERSIONS

Energy in eV ↔ Wavelength in nm:
E[eV] = 1239.841984 / λ[nm]
λ[nm] = 1239.841984 / E[eV]

Energy in eV ↔ Energy in Joules:
E[J] = E[eV] × 1.602176634e-19

Photon count per voxel (at given dose):
N_ph = dose[mJ/cm²] × voxel_area[cm²] × 6.24e15 / E[eV]

9. PHYSICS JUSTIFICATION

Photon energy is fundamentally related to wavelength by E = hc/λ. This is a fundamental physical law, not a parameter.

The CXRO database uses 91.84 eV as a grid point near 13.5 nm. The exact value for 13.5 nm is 91.840147... eV. The difference is ~0.15 meV (0.00016%), negligible for interpolation but important for consistency.

Previous code had two independent sources of truth:
- EUV_WAVELENGTH_NM = 13.5 (primary)
- EUV_ENERGY_EV = 91.84 (hardcoded, not derived)

This caused inconsistency: nm_to_eV(13.5) = 91.840147 ≠ 91.84

Now: Single source of truth (HC_EV_NM + wavelength). Photon energy is ALWAYS derived from wavelength. Changing wavelength in SimulationConfig automatically changes photon energy everywhere.

10. REMAINING ISSUES

- CXRO interpolation uses energy_eV as query point. With configurable wavelength, the exact energy may fall between CXRO grid points. The linear/log interpolation handles this correctly.

- API defaults still use 91.84 eV for backward compatibility. Users should provide wavelength_nm for consistent physics.

- Stochastic module photon_energy_eV default remains 91.84 for API compatibility. When called from pipeline, it should receive the derived energy_eV.

- No changes to material database interpolation logic - only the query energy changes.
