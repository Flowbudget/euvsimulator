1. CODE-PFAD — VOLLSTÄNDIGE REKONSTRUKTION
============================================================
gaussian_se_blur (exposure.py:145-239) — der tatsächliche Operator:
A) Input: 2D-Tensor (dose, n_bar, oder N — alle float32 in der
   Pipeline; aerial.clone().float() → float32, n_bar aus float32,
   N float32)
B) Argumente (alle Aufrufstellen): sigma=se_blur_nm, dx=dx_nm,
   truncate=3.0 (Default), kernel_size=None (berechnet)
C) Kernel: 1D-Gauß x=arange(-r..r, dtype=image.dtype),
   exp(-0.5(x/sigma_px)²), sigma_px = sigma/dx,
   r = int(3·sigma_px + 0.5), kernel_size = 2r+1 (max 3, ungerade)
D) Normierung: kernel_1d /= kernel_1d.sum() (exakt normiert auf
   float32; die 2D-Faltung ist separierbar → Gesamtsumme = 1·1 = 1)
E) Boundary: F.pad(..., mode="circular") in BEIDEN Richtungen
   (col: (0,0,r,r) = Y; row: (r,r,0,0) = X)
F) dtype: working_dtype = image.dtype (Kernel im Input-dtype);
   in der Pipeline immer float32 → identische Kernel
G) Konvertierung: keine (nur der Kernel wird im Input-dtype erzeugt)
H) CPU/GPU: keine separaten Pfade (torch-Operatoren)
I) large_n/legacy: KEINE unterschiedlichen Pfade — beide nutzen
   dieselbe photon_deposition_shot_noise
J) Zweiter impliziter Blur: NEIN — drei GETRENNTE Operatoren auf
   drei GETRENNTEN Größen:
   - se_blur auf N (Energie-Deposition) — stochastic.py:352
   - peb_sigma_diff auf acid (Säure-Diffusion im PEB) — peb.py:282
   - development_correlation_nm auf die Entwicklungsereignisse —
     stochastic_development (STEP 5.3)
   apply_blur=False verhindert jeden weiteren SE-Blur im acid-Pfad
   (exposure.py:289-291: if apply_blur: blur; else: unverändert)

2. OPERATOR-IDENTITÄT — FORMAL
============================================================
H ist die separierbare circular-Faltung mit einem NORMERTEN,
INPUT-UNABHÄNGIGEN Gauß-Kernel:
  - H(x) = conv_circular(x, k⊗k) — LINEAR (keine Nichtlinearität,
    kein Clamp/threshold innerhalb H; der einzige Input-abhängige
    Zweig ist der se=0-Rückgabepfad, der die Identität nicht
    berührt)
  - k hängt nur ab von: (sigma, dx, truncate, Bildgröße, dtype)
  - in der Pipeline sind diese für dose, n_bar und N IDENTISCH
    (gleiche Parameter, gleiche Form (H,W) des Feldes, float32)
  ⇒ H(α·x) = α·H(x) und H(x+y) = H(x)+H(y) EXAKT (algebraisch)

SKALENIDENTITÄT: n_bar = dose·A·f/E_ph (stochastic.py:332-338,
exakte lineare Skalierung, kein Clamp außer n_bar≥0)
  ⇒ H(n_bar) = (A·f/E_ph)·H(dose)  EXAKT
  ⇒ H(dose)·(E_ph/(A·f)) = H(n_bar)  EXAKT (algebraisch)

EMPIRISCH (float32, Ränder eingeschlossen):
  max|H(dose·s) − H(dose)·s| = 3.6e-7 … 1.1e-6  (rel 4e-7 … 1.2e-6)
  für alle Größen (32×128 … 4096×256), se ∈ {2,5,8}, inkl.
  3-Pixel-Randzone (identische Größenordnung) → die Identität gilt
  AUCH AN DEN RÄNDERN (zirkulare BC ist skalenlinear)

BEDINGUNGEN der Identität:
  1. gleiche Parameter (sigma, dx, truncate) — erfüllt (alle
     Aufrufe nutzen se_blur_nm, dx_nm, 3.0)
  2. gleiche Bildgröße (der Kernel wird auf max_dim geklemmt,
     exposure.py:209-213) — erfüllt (dose, n_bar, N haben dieselbe
     Form); Hinweis: bei FELDERN < Kernel (z.B. 64×64 bei se=8:
     Kernel 193 → Clamp auf 63) bleibt die Identität H(dose)·s =
     H(dose·s) gültig (der Kernel ist konstant), nur der Vergleich
     mit dem det.-Pfad (256er-Feld, anderer Kernel!) wäre
     größenabhängig — die Pipeline-Felder sind ≥ 256 → kein Clamp
     → det/stoch-Konsistenz unberührt
  3. gleicher dtype (Kernel wird im Input-dtype erzeugt) — erfüllt
     (float32 überall in der Pipeline)

6. DTYPE / NUMERISCHE IDENTITÄT
============================================================
float32 in der gesamten Pipeline. Die A1≡A2-Identität:
  A1 = H(dose)·e_dep/e_bar
  A2 = e_bar·(E_ph/(A·f))·e_dep/e_bar = e_dep·(E_ph/(A·f))
  max_abs(A1−A2) = 1.9e-6 … 3.1e-5  (bei d_eff-Werten ~0.5-40)
  max_rel(A1−A2) = 1.1e-7 … 6.9e-7
Die Abweichung ist ausschließlich die float32-Rundung der
Einheiten-Konvertierung (H(n_bar) rundet minimal anders als
H(dose)·(E_ph/(A·f))) — die 5.3F-Beobachtung (~1e-7) ist
REPRODUZIERT und erklärt (Maschinen-Epsilon × ~3).
Kein Overflow/Underflow: Wertebereiche 0.5-40 mJ/cm², Kernel-
Summe 1, clamp(min=1e-30) nur als Divisionsschutz.

8. PFADGLEICHHEIT DET vs STOCH
============================================================
det:  dose → H(dose) → acid/PEB/development (pipeline.py:305-332)
stoch: N ~ Poisson(n_bar) → H(N) → d_eff → acid/PEB/development
Mit der neuen Formulierung:
  E[d_eff] = H(dose)  — mathematisch EXAKT (Poisson-Linearität +
  Kernellinearität; empirisch R≈1)
  E[acid(d_eff)] ≠ acid(H(dose)) — die zweite Gleichung darf NICHT
  erwartet werden (Nichtlinearität der acid-Formel); gemessen:
  rel. Abweichung 0.03 % (Jensen-Effekt, KLEIN aber korrekt
  erhalten — NICHT wegkorrigieren)
Der deterministische Mittelwert-Pfad (H(dose)) und die stochasti-
sche Erwartung (E[d_eff]=H(dose)) stimmen überein; die
acid-Mittelung trägt den erwarteten Jensen-Term.
