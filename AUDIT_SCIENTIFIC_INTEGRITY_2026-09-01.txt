HIDDEN ASSUMPTIONS  (evidence ledger)
--------------------------------------------------------------------------------
ID: A1 (sigma-TCC grid saturation)
BEREICH: aerial/abbe.py _compute_tcc_matrix
BEOBACHTUNG: FX, FY fixed in [-2, 2].
  sigma > 2 wird nicht mehr unterschieden (sigma=3 == sigma=10).
MATHEMATISCH: S = (r2 <= sigma**2) auf [-2,2]-Grid.
  Bei sigma ≥ 2.0 füllt die Quelle das gesamte Grid.
RISIKO: P2 — Benutzer kann sigma=5 wählen und keinen Unterschied zu sigma=2
  sehen, ohne Erklärung.
LITERATURSTATUS: unvalidiert.
EMPFEHLUNG: sigma auf [-2, 2] dynamisch skalieren oder Grid adaptive
  machen.
EVIDENZ: FACT (gemessen)

ID: A2 (sigma coarser than 3 orders)
BEREICH: aerial/abbe.py aerial_from_orders
BEOBACHTUNG: Bei 64 nm, NA 0.33 ist max_order=1.
  Es gibt nur Orders -1, 0, 1.
  TCC zwischen sigma=0 und sigma=0.3 identisch (All-1s).
  CD=33.0 nm für sigma ≤ 0.3 (nur durch Amplituden bestimmt).
MATHEMATISCH: Bei ≤3 Orders + TCC ≈ 1 ändert sich die Intensität nicht.
RISIKO: P2 — Benutzer sieht CD=33 für sigma=0 und sigma=0.2 und könnte
  glauben, der Parameter wirke nicht.
EMPFEHLUNG: max_order dokumentieren oder bei max_order<2 NILS/CD-Warnung.
EVIDENZ: FACT (gemessen)

ID: A3 (dose=0 silent clamp)
BEREICH: pipeline.py _cd_via_aerial_threshold
BEOBACHTUNG: dose=0 wird durch max(dose, 1e-9) auf 1e-9 gefaltet.
  threshold scaling = 2e10. Resultat: CD=64 (alles entwickelt).
  Benutzer bekommt KEINE Warnung.
MATHEMATISCH: dose = 0 => kein Licht => keine Reaktion.
RISIKO: P1 — wissenschaftlich gefährlich.
  Ein Benutzer, der dose=0 eingibt, sieht CD=64 und keine Fehlermeldung.
EMPFEHLUNG: dose=0 raise ValueError.
EVIDENZ: FACT (gemessen)

ID: A4 (max_order = 0)
BEREICH: aerial/abbe.py aerial_from_orders Zeile 144
BEOBACHTUNG: Für period ≤ 40 nm bei NA 0.33 ist max_order=0.
  Keine Ordnung wird von der Pupille akzeptiert.
  aerial wird zur Konstanten (DC only, CD=0, NILS=0).
  Keine Warnung, dass das Bild strukturlos ist.
MATHEMATISCH: floor(0.33*40/13.5) = floor(0.978) = 0.
RISIKO: P2 — Benutzer sieht NILS=0, CD=0 ohne zu verstehen warum.
EMPFEHLUNG: Warnung wenn max_order < 2.
EVIDENZ: FACT (gemessen)

ID: A5 (TCC shape parameters hardcoded)
BEREICH: aerial/abbe.py _compute_tcc_matrix Zeilen 526-552
BEOBACHTUNG: Annular: sigma_inner = 0.3*sigma (hardcoded).
  Dipole: pole_sigma = 0.2*sigma, half = 0.3*sigma (hardcoded).
  Quasar: 30° Rotation hardcoded.
  Kein API-Parameter für diese Werte.
  Benutzer hat KEINE Kontrolle über die Quellform-Parameter.
MATHEMATISCH: Die gewählten Parameter sind nicht-physikalische Annahmen.
RISIKO: P2 — Ergebnisse für dipole/annular/quasar sind an diese Defaults
  gebunden, aber das wird nicht dokumentiert.
EMPFEHLUNG: Parameter in SimulationConfig aufnehmen.
EVIDENZ: FACT (Code-Lesung)

ID: A6 (source.py vs _compute_tcc_matrix shape API mismatch)
BEREICH: aerial/source.py vs aerial/abbe.py _compute_tcc_matrix
BEOBACHTUNG: source.py verwendet absolute sigma-Parameter (z.B. sigma=0.2
  für Polradius, separation=0.6). TCC verwendet sigma-Relative
  (pole_sigma=0.2*sigma, half=0.3*sigma). Ein Benutzer, der die source.py-
  API testet und dann run_simulation aufruft, bekommt andere Quellformen
  bei gleicher illumination_shape.
RISIKO: P2 — inkonsistente Defaults.
EMPFEHLUNG: API-Werte harmonisieren.
EVIDENZ: FACT (Code-Lesung)

ID: A7 (nils() default vs pipeline threshold)
BEREICH: aerial/abbe.py nils() vs pipeline.py
BEOBACHTUNG: nils() default threshold=None -> 0.5*mean(cut). Pipeline
  übergibt threshold_val = resist_threshold_norm * mean(aerial) * (20/dose).
  Im Standardfall (dose=20, resist_threshold_norm=0.5) ist das identisch.
  Bei abweichender dose/threshold_norm divergieren die Pfade,
  und nils() OHNE threshold verwendet den falschen Wert.
MATHEMATISCH: Konsistent im Default, inkonsistent bei non-standard.
RISIKO: P3 — direkter nils()-Aufruf ohne threshold könnte irreführen.
EMPFEHLUNG: Nicht ändern, aber Dokumentation der Abhängigkeit.
EVIDENZ: INFERENCE

ID: A8 (interpolierte vs pixel-CD)
BEREICH: pipeline.py _cd_via_aerial_threshold
BEOBACHTUNG: Pipeline-CD = pixel-genau (größter run von dev=0).

MATHEMATISCH: pixel-CD kann systematisch 0..1 Pixel abweichen.
RISIKO: P4 — dokumentiert, keine Änderung nötig.
EVIDENZ: INFERENCE

SCIENTIFIC CONFIDENCE ARCHITEKTUR  (Bewertung)
--------------------------------------------------------------------------------
Der Simulator hat derzeit KEINE Unterscheidung zwischen:
  result
  numerical status
  validation status
  physical domain status
  reference status

SimulationResult enthält:
  cd_nm, nils_value, ler_nm/lwr_nm, status (success/failed/nan_slice).

Es fehlen:
  - domain_warnings (z.B. "sigma>2 grid-saturated")
  - convergence_hint (z.B. "grid may be insufficient")
  - external_validation_status
  - parameter_confidence

Empfehlung für spätere Architektur:
  SimulationResult um optionales `.diagnostics`-Dict ergänzen:
    diagnostics = {
      "max_order": int,
      "tcc_range": (float, float),   # min/max TCC
      "sigma_effective": float,       # actual sigma used
      "warnings": [str],
      "domain_notes": [str],
    }
  Wichtig: DIAGNOSTIC, nicht CONFIDENCE SCORE. Ein Score täuscht
  Präzision vor, die es nicht gibt. Kategorische Warnungen sind
  wissenschaftlich ehrlicher.

Dafür benötigte Daten sind heute bereits im Pipeline-Code verfügbar,
werden aber verworfen (max_order, TCC-Range, etc.).
