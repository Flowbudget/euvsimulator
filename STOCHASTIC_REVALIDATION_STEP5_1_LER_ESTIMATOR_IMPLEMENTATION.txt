2. API-DESIGN
============================================================

  class LEREstimate:
      ler_nm, n_rows, n_eff, l_int_px, l_int_nm, estimator,
      seed_count, uncertainty_nm, ci95_low_nm, ci95_high_nm,
      rho_truncation, disclaimer

  def ler_estimate(
      developed,                 # 2D-Tensor ODER Sequenz (Seeds)
      threshold=0.3, dx=0.25, edge="both",
      intensity=None,            # einzeln oder Sequenz
      estimator="large_n",       # "large_n" | "corr_corrected"
      rho_truncation=None,       # feste Regel: rho<0.05, cap 200 px
      seed_count=None,
  ) -> LEREstimate

  Legacy extract_ler: UNVERÄNDERT (keine Breaking API Change).

============================================================
3. DATENFLUSS
============================================================

  developed/intensity (1 oder N Realisierungen)
    → extract_edges (Sub-Pixel, unverändert)
    → Kantensequenzen pro Zeile
    → RMS-LER (identische Observable wie extract_ler)
    → Autokorrelation rho(k) (gepoolt über Kanten+Seeds)
    → Truncation (erstes k mit rho<0.05, cap 200 px — VORAB
      festgelegt, keine nachträgliche Wahl)
    → L_int = 0.5 + Σ rho(1..K)
    → N_eff = N/(1 + 2Σ(1-k/N)rho(k))
    → optional: Bias-Korrektur (estimator="corr_corrected")
    → LEREstimate (Wert + Metadaten)

============================================================
4. LARGE-N-ESTIMATOR (primär)
============================================================

  estimator="large_n": liefert die RMS-Kantenfluktuation über
  alle Zeilen — DIESELBE Observable wie extract_ler (verifiziert:
  max|diff| = 0.0 auf identischen Feldern) — plus N_eff/L_int.
  Ziel N_eff ≥ 30 wird NICHT hart kodiert, sondern aus der
  empirischen Korrelationslänge abgeleitet (für die aktuelle
  Konfiguration: N ≥ ~2000 Zeilen).

============================================================
5. CORRELATION-CONTROL (Kontrollmethode)
============================================================

  estimator="corr_corrected": LER_korr = RMS·sqrt(N/(N-1)/bias)
  mit bias = 1 − 2·Σ(1−k/N)·rho(k)/(N−1)   [E[s²]=σ²·bias]
  und RMS² = (N−1)/N·s² (exakte Umrechnung).
  Ersetzt den Produktionswert NIE — nur unabhängige Kontrolle.
  Truncation vorab festgelegt (rho<0.05, cap 200 px).

============================================================
6. METADATEN
============================================================

  Pflichtfelder (alle im LEREstimate):
  ler_nm, n_rows, n_eff, l_int_px, l_int_nm, estimator,

   Modellkonfiguration; kein experimentell validierter Wert.")

9. RISIKEN
============================================================

  R1: rho-Schätzung seed-abhängig (L_int ±~1 px) — für den
      Large-N-Primärwert irrelevant; für corr_corrected-
      Kontrolle dokumentieren.
  R2: Interpretationsrisiko — durch Pflicht-Metadaten +
      Disclaimer begrenzt.
  R3: N_eff-Ziel (≥30) erfordert N≥2000 Zeilen — Feldhöhe ist
      Auswerteparameter, keine Physikänderung (späterer
      Produktionsschritt für die Pipeline-Anbindung).
  R4: Dosis-Exponent −0.75 (nicht −0.5) — bekanntes
      Dill-Pipeline-Physikresultat, KEIN Estimator-Fehler;
      bei Bedarf als eigener Physik-Befund zu dokumentieren.
  R5: shift ≥ 10.6 nm degeneriert im 64-nm-Fenster — muss bei
      künftigen Shift-Tests mit Großfeld/Region-Methode
      durchgeführt werden (hier etabliert).
